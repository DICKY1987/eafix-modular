# NEWPHASEPLANPROCESS v3.3.1 — Required Artifacts and Stable Identifiers

## 1. Purpose

This document defines the **required artifact set** and **stable identifier system** needed to keep the NEWPHASEPLANPROCESS v3.3.1 files synchronized, deterministic, and AI-fillable.

The core rule is:

```text
Authoritative files define truth.
Generated files project truth.
Execution files prove truth.
Registry/reconciliation files confirm truth stayed aligned.
```

Generated artifacts must be rebuilt from authoritative source documents, not manually patched. The technical specification explicitly describes `inventory.json`, indexes, and evidence reports as generated projections rebuilt from the authoritative source files.  The instruction document also states that generated inventory, semantic indexes, and evidence reports should not be manually edited; source documents or generators should be updated and rebuilt instead.

# 10. Critical Linking Rules

These are the links that keep files synchronized.

| Link                                          | From                       | To                            | Required stable identifier                                       |
| --------------------------------------------- | -------------------------- | ----------------------------- | ---------------------------------------------------------------- |
| Authoritative source → generated artifact     | Template/spec/instructions | Generated output              | `source_file`, `source_hash`, `source_pointer_id`, `artifact_id` |
| Generated artifact → manifest                 | Generated output           | `generation_manifest.json`    | `artifact_id`, `output_hash`, `generator_id`, `logic_hash`       |
| Section → gate                                | Template section           | Validation gate               | `section_id`, `gate_id`                                          |
| Gate → evidence                               | Validation gate            | Evidence folder/file          | `gate_id`, `evidence_id`                                         |
| Phase → step                                  | `phase_contracts`          | `step_contracts`              | `phase_id`, `step_id`, `phase_step_key`                          |
| Step → artifact intent                        | Step output/mutation       | `artifact_intent_manifest`    | `phase_step_key`, `artifact_intent_id`                           |
| Artifact intent → file manifest               | Planned mutation           | File scope/inventory          | `artifact_intent_id`, `path_key`                                 |
| Artifact intent → registry projection         | Planned artifact           | Planned registry row          | `artifact_intent_id`, `projection_id`                            |
| Registry projection → observed registry write | Planned registry row       | Runtime observed registry row | `projection_id`                                                  |
| Step → pattern                                | Step contract              | Execution pattern             | `phase_step_key`, `pattern_id`                                   |
| Step → executor                               | Step contract              | Executor registry             | `phase_step_key`, `executor_id`                                  |
| Pattern → executor                            | Pattern registry           | Executor registry             | `pattern_id`, `executor_id`                                      |
| Executor → config                             | Executor binding           | Config/schema files           | `executor_id`, `config_schema_file`, `config_instance_file`      |
| Step/artifact → path resolver                 | File references            | Physical path                 | `path_key`                                                       |
| Step/artifact → abstraction contract          | Governed boundary          | Boundary contract             | `abstraction_contract_ref`                                       |
| Step/artifact → reusable program              | Work action                | Shared runner/program spec    | `reusable_program_ref`                                           |
| Planned output → observed evidence            | Plan                       | Runtime evidence              | `artifact_intent_id`, `phase_step_key`, `evidence_id`            |
| Planned registry projection → reconciliation  | Planned metadata           | Observed runtime facts        | `projection_id`, reconciliation gate                             |

The uploaded list summarizes the main drift-prevention chain as authoritative source files → generated artifacts → plan instance → step contracts → artifact intent → file manifest → planned registry projection → observed outputs/evidence → reconciliation gates.
